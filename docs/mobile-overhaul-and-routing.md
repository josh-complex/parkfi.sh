# Mobile Overhaul + Pedestrian Routing — Handoff

Status as of this writing: **shipped in the working tree, not yet deployed.** All
code type-checks and tests pass (`bun vp check`, `bun vp test`). The one piece
that is **not runnable end-to-end** is pedestrian routing, because it depends on a
self-hosted Valhalla service that still has to be deployed and pointed at via
`VALHALLA_URL` (see [Routing](#pedestrian-routing-valhalla)).

This document is the source of truth for the mobile redesign and, especially, the
routing feature. Read the [Routing](#pedestrian-routing-valhalla) section in full
before touching anything map/nav related.

Conventions: coordinates are **`[lng, lat]`** everywhere (GeoJSON / MapLibre
order) unless a name says otherwise. Run all bins through `bun` (no `node` on PATH):
`bun vp check`, `bun vp test`.

## 1. What changed (mobile overhaul)

The mobile UX was rebuilt around a **map-first, drawer-nav** model:

- **Bottom nav island** (`src/components/mobile-bottom-nav.tsx`) — a `md:hidden`,
  `fixed` connected 3D segmented bar (reuses the `btn-3d-*` / `shadow-3d` /
  `border-3d` system from `styles.css`): Waits · Tickets · **Map (raised center)** ·
  Eats · Stays. All segments share edges (`-ml-px`) with `items-end` so bottoms
  line up; the Map key is taller, white when idle, and fills primary + depresses
  (`top-[3px]` + `shadow-3d-active`) when its route is active. Mounted once in
  `AppInset`, so it appears on every dashboard-shell route. `--bottom-nav-height`
  (set on `AppInset`) reserves space; the content card and the Eats/Stays filter
  FABs offset against it.
- **Top bar** (`src/components/site-header.tsx`) — backgroundless on mobile
  (`pointer-events-none` header, interactive children re-enable it) so the map
  shows behind. It's a single full-width **inset search bar** (`border-t-[3px]`
  like our inputs) containing the search trigger + the account avatar on the
  right. The hamburger is gone; the avatar opens the account menu.
- **Account menu** (`src/components/mobile-user-menu.tsx`) — a **vaul Drawer**
  (bottom sheet), NOT a Base UI popover-menu. Base UI `Menu`'s synchronous
  `flushSync`-on-open collided with the teleported map host and threw "removeChild
  of null" (see [Gotchas](#gotchas--hard-won-lessons)). It surfaces Pins, Forecast,
  Notifications (`/alerts`), theme toggle, Account settings, and auth.
- **Morphing search placeholder** — the search says "Search for <morphing subject>"
  using `src/components/ui/morphing-text.tsx`. Two knobs added to that component:
  `smooth` (drop the gooey SVG threshold filter — it erases small text mid-morph)
  and `fit` (inline-grid content-sizing so the morphing word stays truly centered
  instead of left-aligned in a fixed box), plus `morphDuration` / `pauseDuration`.
  The rotating list is `SEARCH_HINTS` in `site-header.tsx`. `OmniSearch` gained a
  new `variant="inline"` for this embed (see `omni-search.tsx`).
- **Waits page** (`/`, `src/components/rides/cross-park-waits.tsx`) — replaced the
  stats overview with a **unified cross-park ride list**, grouped by park,
  sortable (wait / A–Z), filterable, backed by the new `parks.allRides` query.
- **Map page** (`/map`, `src/routes/_dash/map.tsx`) — the map is now a real page:
  a `fixed inset-0 z-0` full-viewport layer on mobile, with the top bar (z-30) and
  bottom nav (z-40) floating over it. See [Map architecture](#2-map-architecture).
- **Clustering** (`src/components/park-map/declutter.ts`) — spiderfy removed
  entirely. Tapping a cluster now zooms to fit its members (`onZoomToCluster`).
  `DECLUTTER_SIZE` (in `shared.tsx`) tuned so pins only merge on real overlap.
- **Ride filter** (`src/components/rides/ride-filter*.tsx`) — a shared filter
  (category / open-only / max-wait / no-height-requirement) via `RideFilterProvider`
  (mounted in `_dash.tsx`), a drawer UI (`RideFilterButton`), and a pure predicate
  `rideMatchesFilter`. Applied to both the map markers and the Waits list.
- **Geolocation** — `src/hooks/use-geolocation.ts` + a "locate me" control; auto-
  focus into the park you're standing in. See [Geolocation](#4-geolocation).
- **Basemap (owner's later change)** — the MapLibre renderer now uses **MapTiler**
  vector styles (`VITE_MAPTILER_KEY`), strips POI/place labels so our node labels
  win, and overlays baked in-park coaster/slide tracks from
  `public/park-tracks.geojson` (regenerated by `scripts/build-park-tracks.ts`).
  This is orthogonal to routing but shares `park-map.tsx`.

## 2. Map architecture

There is **one** map instance (a WebGL MapLibre map, or a Leaflet fallback when
WebGL is unavailable) that is **teleported between routes**, never remounted.

- `src/components/park-map/map-stage.tsx` — `MapStageProvider` owns the singleton.
  The map renders (via `createPortal`) into a plain DOM `host` node that is
  **not** a React child; `MapSlot` layout-effects `appendChild` that host into
  whichever route mounts a slot, and a FLIP `morph()` animates the box between
  slots. **Do not make `host` a React child** — moving a React-owned node by hand
  desyncs the fiber tree and crashes with "removeChild of null".
- `MapStageProvider` also owns: geolocation (one watch for the whole app), the
  ride filter (`useRideFilter`), the walking-directions state, and the floating
  overlay controls (locate button, filter button, directions panel) — all rendered
  inside the portal so they travel with the map.
- Renderers: `park-map.tsx` (MapLibre, primary) and `park-map-leaflet.tsx`
  (fallback). They are kept feature-parity; **any map behavior change must be made
  in both.** Shared marker/popup/DOM builders live in `shared.tsx`.
- **Free-roam** (`roam` prop, true only on `/map`): the renderer self-manages
  which park is focused from zoom + viewport center (`pointInPolygon` against park
  boundaries) — no route navigation. Zoom in over a park → its rides appear; zoom
  out (< `ROAM_RIDE_ZOOM`, =14) → park badges return; tapping a park badge flies
  in. Elsewhere the map is route-driven by `activeSlug`. `MapStageProvider` sets
  `roam = pathname === "/map"` and suppresses the navigate-based auto-zoom there.

## 3. Pedestrian routing (Valhalla)

**Goal:** "route to a destination while in a park" on real OSM footpaths, with no
third-party routing API. We self-host **Valhalla** and call it from our own tRPC.

### 3.1 Data flow (end to end)

```
Attraction popup "Directions" button (shared.tsx, data-directions + data-lng/lat)
   │  renderer intercepts the click → onRequestDirections({id,name,coords})
   ▼
MapStageProvider.requestDirections (map-stage.tsx)
   │  snapshots the user's current location as the trip ORIGIN (so the route
   │  doesn't refetch/reframe on every GPS tick); if location isn't granted yet
   │  it stashes the dest + calls geo.locate(), then fulfills on the first fix.
   ▼
trpc.routing.route.useQuery({ from:[lng,lat], to:[lng,lat] })   (enabled when trip set)
   ▼  (server)
routingRouter.route  (src/integrations/trpc/routers/routing.ts, publicProcedure QUERY)
   ▼
fetchRoute(from, to)  (src/server/routing/valhalla.ts)
   │  POST {VALHALLA_URL}/route  { locations:[{lat,lon}×2], costing:"pedestrian",
   │                               directions_options:{units:"kilometers"} }
   │  response: trip.legs[].shape (encoded polyline, PRECISION 6) + maneuvers,
   │            trip.summary.length(km)/time(s)
   │  decodePolyline(shape, 6)  → [lng,lat][]   (src/server/routing/polyline.ts)
   ▼  RouteResult { coordinates:[lng,lat][], distanceMeters, durationSeconds, maneuvers[] }
   ▼  (back in map-stage)
route line drawn on the map + a floating ETA/Directions panel; clear button resets trip
```

### 3.3 The Valhalla service (must be deployed)

`valhalla/Dockerfile` wraps the gis-ops `docker-valhalla` image. On first boot its
entrypoint downloads the OSM extract named in `tile_urls` and **builds routing
tiles** into a mounted data volume; later boots reuse them (`use_tiles_ignore_pbf`).
Valhalla serves HTTP on **:8002**; we call `POST /route` with pedestrian costing.

**Deploy checklist (Railway) — see `valhalla/README.md` for detail:**

1. New Railway service from `valhalla/Dockerfile`.
2. Attach a **persistent volume** at the data dir (`/custom_files`); Florida tiles
   are a few GB → provision ~4 GB. First deploy builds tiles (slow, minutes).
3. Recommended: pre-clip the Geofabrik Florida extract to an Orlando bbox with
   `osmium extract` for a much faster/smaller build (only the parks region is ever
   routed).
4. **IPv6 caveat (important):** Railway's private network is IPv6-only. Valhalla's
   HTTP server defaults to `tcp://*:8002` (IPv4 only), so `*.railway.internal`
   calls get `ConnectionRefused`. Either (a) call it over the service's **public**
   domain and set `VALHALLA_URL` to that `https://…`, or (b) make Valhalla listen
   `tcp://[::]:8002` and use the internal host. (Same lesson as our Nitro `::`
   binding.)
5. Set on the **ParkFi** service: `VALHALLA_URL=<public https url>` **or**
   `valhalla.railway.internal:8002` (schemeless is fine — `normalizeBaseUrl` adds
   `http://` + port). Optional `VALHALLA_TIMEOUT_MS`.

Until `VALHALLA_URL` points at a running Valhalla, the Directions button will show
the loading/error state (the query fails against `localhost:8002`). Everything
else works without it.

### 3.4 Coordinates available for routing

`parks` and `attractions` both carry `latitude`/`longitude` (`src/db/schema.ts`),
enriched from public feeds. `parks.list` returns park `boundary` (GeoPolygon) used
for point-in-polygon; `parks.board` / `parks.allRides` return attraction lat/lng
used as routing destinations and marker positions.

## 4. Geolocation

- `src/hooks/use-geolocation.ts` — wraps `navigator.geolocation`. **Never
  auto-prompts**; the consumer calls `locate()` from a user gesture. Discriminated
  `GeoState` (`idle | prompting | granted{coords[lng,lat],accuracy,heading} |
denied | unavailable | error`); guards SSR + insecure context. `watch: true`
  keeps a live `watchPosition`.
- Owned in `MapStageProvider` (one watch app-wide, survives navigation). Drives:
  the "you are here" marker (`buildUserLocationEl` in `shared.tsx`) on both
  renderers, the locate button, and auto-focus.
- Auto-focus/zoom uses `pointInPolygon` + `distanceMeters` from
  `src/server/living/geofence.ts` (pure, `[lng,lat]`, client-import-safe — reused,
  not reimplemented). On the overview it navigates into the containing park; in
  `/map` free-roam it flies+focuses in-place.
- **Requires HTTPS** (secure context). Fine on Railway/CF and `localhost`.

## 5. Key routes & queries

- `/` → `_dash/index.tsx` → `CrossParkWaits` (unified ride list). Loader prefetches
  `parks.allRides`.
- `/map` → `_dash/map.tsx` → fullscreen `MapSlot` (free-roam). Loader prefetches
  `parks.overview`.
- `/park/$slug` → the per-park dashboard (route-driven map + board table); reachable
  on desktop and via deep links / ride "More info". Mobile primary flow stays on
  `/map`.
- New/changed tRPC: `parks.allRides` (cross-park ride list w/ schedule gating &
  ghost-dup `category IS NOT NULL` filter) and `routing.route`.

## 6. Gotchas / hard-won lessons

- **"removeChild of null" = the teleported map host.** Any modal/popover that does
  a synchronous full-root commit (Base UI `Menu`) can collide with the imperative
  host on `/map`. Use vaul Drawers for mobile menus on map pages. Keep `host` a
  non-React node.
- **Two renderers.** Every map change goes in `park-map.tsx` AND
  `park-map-leaflet.tsx`. (Currently both draw the route; MapLibre re-adds the
  route/boundary/track layers on `styledata` after a style swap.)
- **`border-t-3` is not a generated utility here** — use `border-t-[3px]`.
- **MorphingText threshold filter** erases small text mid-morph → use `smooth`.
  Fixed-width morph box left-shifts text → use `fit` for centered inline use.
- **Polyline precision 6** for Valhalla, not 5.
- **`import.meta.env` server vars don't populate at runtime on the Node server** —
  read routing/service URLs from `process.env` (as `valhalla.ts` and `embed.ts` do),
  not via `src/env.ts`.
